## Findings considered and rejected

So they are not re-audited next run:

- **Replace/restore deleting photos is by design (ADR-0006/PHO-005).** The
  defect is the misleading “snapshot saved first” copy and the inaccessible
  data snapshot, not the photo-exclusion policy. Plan 002 fixes the copy and
  data recovery; no photo trash is planned.
- **The JSON document store instead of Drift is the documented interim
  design.** It is not a finding; it is the direction item below.
- **`cupertino_icons` unused.** Real, but removing a direct pin requires
  regenerating the lock and has little user value. Plan 010 corrects the ledger
  note; removal is a P3 quick-fix if the owner wants it.
- **Release Gradle gates keyed to exact `assembleRelease`/`bundleRelease`
  names.** Latent only; there are no flavors today. Not planned; revisit when
  a flavor is added.
- **Golden-coverage guard only checks PNG existence.** P3 test hardening; not
  in this batch. A new screen can currently ship without a golden.
- **Duplicated import/restore flow in `backup_section.dart`.** P3 refactor; the
  behavior is correct and tested. Do it after 002/011 if the file keeps
  growing.
- **`verify.sh` fail-open if `project-verify.sh` loses its exec bit.** The
  template fallback requires a literal `- Primary users:` line that
  `docs/PRODUCT.md` does not contain, so the lane fails non-zero today. Not a
  finding; Plan 009 covers the guards that actually fail open.
- **`dataExtractionRules` presence-only Gradle check.** The rules file content
  is pinned by `test/photos/photo_privacy_test.dart`; the ADR sentence
  overstates which check enforces it, not the control. Plan 010 does not change
  requirement status.
- **Photo decompression bomb.** The picker resizes before Dart sees the file
  and the source is capped at 40 MB; no reachable unbounded decode was found.
- **Verified clean:** `_mutate` rollback/`restoreFromBackup` commit semantics;
  snapshot retention with a backwards clock; merge ID/reference conflicts;
  prefill/progression/PR rules; photo path traversal; external link scheme
  injection; merged release manifest; CI secret handling; EXIF/GPS removal;
  JSON/backup photo exclusion; no secrets in the tree or history.

## Direction (not planned in this batch)

- **M1 Drift / incremental persistence.** The JSON document is rewritten,
  revalidated, and re-encoded on every mutation; the quality/architecture docs
  mandate migration snapshots and Safe Mode that do not exist. A design spike
  should use plan 004's measurements, compare an incremental JSON layout with
  Drift, define the JSON-v2 import path, and decide. This is the structural fix
  for `NFR-PERF-002` and update safety; it is a multi-day owner decision, so it
  is not a hidden implementation step.
- **Recovery as a product surface.** Plan 002 makes data snapshots restorable
  and the photo warning honest. A later Safe Mode surface (raw-document export,
  diagnostics, newer-schema variant) would complete the `DAT-004` target design;
  it needs an owner decision on what the app may export.
- **Close device evidence and regression budgets together.** All device budgets
  remain `UNPROVEN` and the CI gate is far looser than its docs; plan 008 adds
  a regression floor, but only a reference-device profile run can close
  `NFR-PERF-001/002/004/005/006`.
